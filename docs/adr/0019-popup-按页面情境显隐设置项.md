# popup 按页面情境显隐设置项

**状态**: accepted

**决策**: popup 把设置项按**页面情境**分成三组——**全局项**（插件总开关、清空全部记忆）常显；**直播专属项**（全屏显示醒目留言、SC 显示位置）只在直播页出现；**视频专属项**（彻底隐藏已屏蔽内容、清空屏蔽记录）只在视频页出现。分区是**双向的**：不只藏掉直播间里不会生效的「不感兴趣」开关，也藏掉视频页里不会生效的 SC 设置。判定**只看标签页地址**（与 manifest 的 `content_scripts.matches` 同构），不等 content script 应答；情境为「未在 B 站视频/直播页」时**不做任何过滤，全部设置项照常显示**。原先那行「当前页面 → 视频页/直播页」被撤下（用户本来就能从页面上看出来），该行降级为**纯状态行**，只在有话要说时出现。

**要解决的问题**: popup 九行设置里，对某一类页面真正有用的只有两三行——直播间里摆着「彻底隐藏已屏蔽内容」与屏蔽记录计数、视频页里摆着「全屏显示醒目留言」与「SC 显示位置」，都是点了也不会生效的噪声，把真正该调的那两项淹掉了。而「当前页面 → 视频页」这行更是把用户一眼可见的事实复述了一遍，偏调试向。

**理由**:

- **判据用地址，不用消息应答。** `content.js` 的 `detectType()` 本就只看 hostname，与 manifest 的 `matches` 同源；直接按地址判定，popup 打开瞬间就能定型，既不会出现"先按未知渲染、几百毫秒后才补上"的闪烁，也不受 content script 是否已注入影响（页面刚加载时 `getState` 是拿不到的）。
- **未知情境一律不过滤。** 分区是为了减少干扰，不是为了隐藏能力。插件无法确定页面类型时（非 B 站页面、B 站其他页面），藏掉任何设置项都只是让用户找不到东西；此时全部显示，行为可预期。
- **不加"设置去哪了"的解释性提示。** 视频页里 SC 两项被隐去时不附任何说明文字——提示行本身就是净增的噪声，而 SC 的语义（醒目留言只存在于直播）足以自证。
- **「当前页面」行不该删，该降级。** 它原本兼着四条文案的落点：`未在 B 站视频/直播页`、`尚未就绪，请刷新页面`、`已清空记忆`、`已清空屏蔽记录`。整行删掉等于拆掉这些文案的家；改为按内容显隐，在 B 站页且已就绪时整行不存在，其余场合照常出现。

**取舍**:

- **不给视频页留 SC 设置的入口。** 想调 SC 就得先打开一个直播间。可发现性明确让位于干扰控制——这是本决策的核心取向。
- **操作反馈 2.5 秒后自动回落。** 清空记忆 / 屏蔽记录后状态行短暂顶为反馈文案，随后回落到情境状态（B 站页即整行消失），避免这行在操作后永久驻留、又变回噪声。
- **「UP 主」「当前增益」两行保留且不分区。** 它们不属于"用户自己看得出来"的那类：增益是插件独有状态、页面上没有等价物；识别结果同理（页面上能看见名字，但看不见插件认成了谁）。
- **记忆计数按情境只报相关那一半。** 直播页只报直播配额、视频页只报视频配额，未知情境保留全量——同一个原则顺路收拾干净。
- **tips 区不参与分区。** 快捷键与音量模型是两类页面共用的说明，只有「不感兴趣」那条是视频专属；拆散它得不偿失，故整块保持常显。

**落地细节（已定）**:

- `popup.html`：情境专属行加 `data-ctx="live|video"`；因 `.row` 的 `display: flex` 会盖过 UA 的 `[hidden]`，补一条 `.row[hidden] { display: none; }`。状态行加 `id="statusRow"` 并默认 `hidden`。
- `popup.js`：新增 `pageContext(url)`（`live.bilibili.com` → 直播；`search.bilibili.com` 与 `www.bilibili.com/video|list` → 视频；其余 → 未在 B 站）、`applyContext()`、`setStatus()`、`flashStatus()`、`countText()`；`refreshState()` 先定情境并按情境过滤，再取 content script 状态。
- 页面情境判定与 `content.js` 的 `detectType()` **同源但各写一份**：前者判"该给用户看哪些设置"，后者判"脚本该走哪条播放器适配路径"。两份规则重合是巧合而非契约，故不做跨进程同步。
