# 0015-SPA 导航：页面身份与重识别

**状态**: accepted

**症状（实测）**: 在视频页内点推荐位、自动连播、切分P 或 `/list/` 合集换集后（**没有**新开页面，只在同一页面跳转、地址栏随之改变），插件的增益不再跟随 UP 主切换——上一个视频的增益被原样套用到下一个视频；在新视频上调音量，写进的也往往是**上一个 UP 主**的记忆键。

**根因**:
1. 全仓**没有任何 URL 变化监听**（`popstate` / `hashchange` / `pushState` / `replaceState` / Navigation API 零命中）。B 站视频页之间是同文档导航：地址栏变了、content script 不重新注入，只有 `window.__INITIAL_STATE__` 被路由原地改写。
2. `sniff.js`（MAIN world，UP 主识别的主通道）只在加载期轮询 `[500,1500,3000,6000]` ms 就**永久停手**，导航后不再重读全局状态。
3. `domSniff()`（DOM 兜底）的短路闸门 `hasUpEvent[type] && current.mid` 在首次事件后**永不重置**，于是 2 秒轮询每轮都立刻 return。
4. 三者叠加 → `current.mid` 停在旧 UP 主 → `setCurrent()` 的"变化"判定不成立 → `applyMemoryGain()` 不执行 → 引擎这个整会话单例上的旧增益原封不动继续生效。
5. 独立第二缺陷：`applyMemoryGain()` 在 `memo == null` 时**什么都不做**。即使 mid 正确更新，"新 UP 主没有记忆"这条路径同样会残留旧增益。

**决策**:
1. **导航信号由 MAIN world 提供**：`sniff.js` 在顶层窗口包装 `history.pushState/replaceState` 并监听 `popstate`/`hashchange`，导航时派发 `bv_boost_nav`（供主逻辑立刻清空识别状态），随后**读到 UP 主变化为止**地重读全局状态再派发 `bv_boost_up`。放宽期（1200ms）过后仍无变化就先派发当前值（同 UP 主换集走这条），之后转慢轮询至 8s 兜住路由延迟。
2. **判定粒度是「页面身份」而非原始链接**：视频页取 bvid（`/list/` 合集的 bvid 在 query 里）、直播页取路径首段数字；`?t=` / `?p=` / `spm_id_from` 等参数不参与。身份未变则什么都不做。
3. **重识别不重建引擎**：新增 `reinstate()` 统一"嵌入帧挂钩 → 识别 → 视频挂载 → UI → 记忆应用 → SC → 不感兴趣"七步，供首绑 / 2 秒兜底 / 导航事件共用。只清空识别状态，音频管线保持不动。
4. **无记忆 → 显式回默认 100%**：`applyMemoryGain()` 改为 `setBoost(memo != null ? memo : 100)`，并由 2.5 秒兜底定时器覆盖"完全识别不出 UP 主"的情形。
5. **闸门改为按身份重新武装**：身份变化时清空 `hasUpEvent` 与 `current.mid`，让 DOM 兜底对新页面恢复工作——但不删除闸门本身。

**理由**:
- 复用现成的 MAIN↔ISOLATED 自定义事件桥（ADR-0013 已建），零新增权限、零新增注入时机；在隔离世界重造一份 URL 监听还得再解决"读不到全局状态"的问题。
- "读到变化才收工"是必须的：路由**异步**拉数据再改写 `__INITIAL_STATE__`，导航瞬间读到的仍是上一个视频的 UP 主；若就此当成新值送去，旧增益照旧套到新视频——正是本 ADR 要修的故障。
- 以身份而非 href 为粒度：B 站频繁用 `replaceState` 更新 `?t=`/`spm_id_from` 之类的参数，按 href 判定会让增益在播放中无故抖动；同 UP 主切分P 也不该被当成换页。
- 重识别不动引擎：`teardown()` 会停抽头音轨并还原 muted，制造无声窗口，与 ADR-0011「绝不整页无声」直接冲突；而 video 元素的复用与重建分别由 `bindVideo` 与引擎自身的重抽（recapture）覆盖，无需外力。

**取舍与后果**:
- **增益在识别完成前保持不动**（不立刻回默认）：避免同 UP 主换集时出现"记忆值→100%→记忆值"的听感抖动；代价是识别窗口内（实测通常 <500ms，最长 2.5s）仍是旧值。窗口期视频多在缓冲，听感影响可忽略。
- 识别窗口内 `current.mid` 为空，此时用户若调音量，`persistBoost()` 会因 `!current.mid` 提前返回而**不写记忆**——该次调整丢失，但不写错键。
- 若路由耗时超过 8s 且全程读不出变化，会退回"上一次读到的值"，极端情况下仍可能停在旧 UP 主；此时 2 秒轮询的 `onNavigation()` 身份比对与 `domSniff` 是第二、第三道防线。
- 嵌入帧（`blanc` 异形直播间）内也跑着 `sniff.js`，但其 history 属于帧自身，故导航钩子只在 `window.top === window` 时安装（见 ADR-0013）。
