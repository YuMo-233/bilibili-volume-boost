# 详情页相关推荐不感兴趣按钮:原生通道上报 + 自绘像素级复刻

视频详情页右侧「相关推荐」卡片缺少主页卡片自带的「不感兴趣（⋮）」入口，用户要反馈必须离开当前页。决定：在推荐卡片右下角注入常驻 ⋮ 按钮，复用 B 站原生上报通道（真正内联推荐系统，非本地假移除），UI 用 Shadow DOM 自绘并逐项复刻原生观感与交互。

## Status

accepted

## 决策要点

- **上报通道**：`POST https://api.bilibili.com/x/web-interface/feedback/dislike`；撤销 `POST .../feedback/dislike/cancel`。请求体与真机抓包逐字段一致：
  `app_id=100&platform=5&goto=av&id={aid}&mid={UP主mid}&feedback_page=1&reason_id={1|4}&csrf={bili_jct}`。
  实测该接口**不校验 WBI 签名**，携带页面 cookie 即可（`credentials: 'include'`），故无需在扩展内实现 WBI/密钥轮换。
- **菜单结构（实测修正）**：原生 ⋮ 菜单**只有两项直达**——「内容不感兴趣」`reason_id=1`、「不想看此UP主」`reason_id=4`，点击即上报，**不存在二级理由菜单**。这与真实页面和用户首张截图一致。原先设计假设的「理由清单二级菜单」经实测证伪，弃用。
- **视频身份纯 DOM 提取（零网络请求）**：bvid 取自卡片 `/video/BV...` 链接，UP 主 mid 取自 `space.bilibili.com/{mid}` 链接；接口要的 `aid` 由 bvid **本地换算**（base58 解码 + 掩码异或），已用真实数据校验一致，不额外请求 `view`/`related` 接口。
- **像素级还原**：样式全部取自真机 computed style（⋮ 图标 18px、色 `rgb(167,160,148)`；菜单底 `rgb(24,26,27)`、圆角 12px、项高 40px、字号 14px、悬停底 `rgb(31,34,35)`；浮层底 `rgba(24,26,27,.4)`、圆角 6px、皱眉图标 36px、标题 14px/说明 12px、撤销按钮 `rgba(24,26,27,.2)`+内边距 6px 12px+13px 字号），图标 path 原样嵌入。不靠截图临摹。
- **交互还原**：⋮ 常驻卡片右下角（与播放量行齐平），**鼠标移到 ⋮ 上弹出菜单**，点击条目直接上报。
- **已反馈态照搬原生三件事**（规则取自 B 站 `index-*.css` 与真机 computed style）：① **封面磨砂**——封面图外层 `filter: blur(20px)`，带 `.3s` 过渡；② **浮层只盖封面**——绝对定位贴封面矩形，底色 `rgba(24,26,27,.4)`、圆角 6px、`opacity` `.3s` 淡入；③ **隐藏标题信息区**——原生是整块不再渲染（卡片高度 223→148，正好只剩封面），插件改为 `.info { visibility: hidden }` 保位，避免横版列表跳动。
- **小封面适配**：详情页推荐卡是横版、封面仅 141×80，放不下原生尺寸的浮层内容（约需 218px 宽）。经确认采用「浮层只盖封面」并把内容按比例缩小、由横排改竖向堆叠（图标 22px、标题 11px、说明 10px、撤销按钮 3px 8px / 11px）。这是有意的几何适配，其余色彩、圆角、动效时长与原生一致。
- **注入位置：绝不动宿主框架管理的 DOM**。B 站视频页是 SSR + hydration（`#mirror-vdcon`），早期实现把插件节点插进推荐卡片内部，破坏了 hydration，触发 B 站重新挂载（控制台出现 `already an app instance mounted`、白屏检测介入），表现为进入详情页卡顿一下、页面像重载、**顶部导航栏整条消失**。改为在 `document.body` 上挂自有图层（`DislikeLayer`），图层内为每张卡片建一个绝对定位 slot，按卡片在文档中的坐标换算位置，宿主 DOM 结构零改动；已反馈态所需的封面磨砂与信息区隐藏只改**内联样式**，不增删节点。
- **定位用文档坐标**：图层挂 body、slot 用文档坐标，页面滚动天然跟随，无需每帧重算。重定位采用 rAF 节流的"先批量只读测量、再批量写入"（`measure` / `applyGeometry`），几何未变时不写样式，避免逐卡读写交替造成反复重排（layout thrash）。
- **当前视频开关**：在视频页操作栏「点赞 / 投币」之间加一个开关控件，点一次上报「不想看此UP主」`reason_id=4`，再点一次撤销（激活变蓝 `#00AEEC`）。**只放图标不放文字**——图标复用点赞路径垂直翻转（即"踩"的形态），悬停显示「不感兴趣」提示。
- **为什么不留文字（间距问题）**：实测操作栏容器 668px = 左组 400（4 项各 92 宽 + 8 间距，**步距 100**）+ 右组 197（稿件举报 78、记笔记 65、⋮ 24），**只剩 71px 空余**。原生项之所以透气，是因为「92 宽里内容只占约 66px，余下约 26px 是项内留白」，故相邻项视觉间距约 34px。要放文字需约 82px 内容 + 26px 留白 = 108px 项宽，远超 71px 余量。经确认只保留图标：本项定为「图标 24 + 项内留白 26 = 宽 50」，让位 58px，左右视觉间距都恰好 34px，**与原生完全一致**；余量不足以让位时宁可不显示，绝不挤压原生按钮（早期版本未做此判断，曾把右组「记笔记」压成 0 宽）。
- **差评（点踩）不可实现，故未做**：网页端不存在点踩接口——逐个探测 `/x/web-interface/archive/dislike`、`/x/web-interface/view/dislike`、`/x/web-interface/archive/hate`、`/x/v2/view/dislike` 全部返回 404 HTML；唯一接口 `app.biliapi.net/x/v2/view/dislike` 为 **App 专用，必须 App 登录令牌 `access_key`**（浏览器只有 SESSDATA/bili_jct），且该域被 CORS 拦、不携带 `.bilibili.com` cookie。因此该开关只承载「不感兴趣」这一真实可用信号。
- **卡片不离开列表**：上报后卡片原位进入已反馈态，撤销即恢复原状，故不采用「移除卡片 + 插入占位」方案。
- **会话去重**：已上报的 bvid 记入会话集合，再次出现不再注入按钮、不重复上报。
- **未登录**：读不到 `bili_jct` 时不注入按钮。
- **注入范围**：仅含 `/video/BV...` 链接的 UGC 视频卡；番剧/直播/广告卡有各自理由体系与上报参数，不混入。

## Considered Options

- **直接复用主页卡片的原生 DOM 节点**：依赖原生组件结构与内部弹菜单逻辑，B 站改版即失效；否决，选自绘 + 原生接口（与 SC 浮层同一已验证路线）。
- **本地假移除不上报**：无真实推荐降权效果；用户明确要求内联原生通道，否决。
- **自行实现 WBI 签名**：需内嵌 MD5 且密钥按日轮换，实测该接口并不校验签名，纯属多余复杂度，否决。
- **上报后移除卡片**：会造成列表跳动，且与原生「原位覆盖」行为不符，否决。

## Consequences

- 新增 `https://api.bilibili.com/*` host 权限；上报以页面身份携带 cookie 完成。
- 依赖 `aid` 的本地换算表与算法，若 B 站变更 BV 编码规则需同步更新（算法集中在一个静态方法内）。
- 卡片需成为定位上下文：注入时若卡片 `position` 为 `static` 则补 `position: relative`（Vue 重渲染会还原，下一轮扫描自动补回）。
- 样式基线随 B 站改版可能漂移，改版后需重新采集比对。
