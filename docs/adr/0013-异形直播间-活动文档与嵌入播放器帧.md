# 0013-异形直播间：活动文档与嵌入播放器帧的跨文档适配

**状态**: accepted

**症状（实测）**: 部分直播间（活动/特殊模板，如 live.bilibili.com/88888「生日会」）插件**全功能失效**：无音量按钮、无增益（引擎不挂载）、Alt 快捷键与沉浸全屏 SC 浮层均不工作。

**根因（真实页面取证）**: 这类房间把**整个直播间的 DOM**（播放器 + 聊天 + 礼物栏 + 活动 UI）嵌在同源 iframe 内：`https://live.bilibili.com/blanc/{真实房间号}?liteVersion=true`（外层 `.live-non-revenue-player > .player`），顶层文档只剩空壳——0 个 `<video>`、无控制栏、无任何音量类元素。而原实现的一切播放器域查询与监听都在顶层文档上：
- `findVideo()` 取不到 video → 引擎永不挂载；
- UI 槽位/锚点均不命中 → `mount()` 直接失败；
- `keydown` / `pointerdown` / `fullscreenchange` 挂在顶层文档 → 焦点在帧内时全部收不到；
- SC 浮层注入点 `.live-player-mounter` 在顶层不存在；且沉浸全屏发生在帧内时，顶层浮层不在全屏子树内、不可见。

**决策（顶层集中 + 活动文档，单实例）**:
1. **活动文档**抽象：`actDoc()` 解析嵌入帧文档（`iframe[src*="/blanc/"]`，同源可访问；跨源/未就绪时退回顶层）。播放器域的一切查询与 DOM 注入落到活动文档：video 查找、UI 宿主创建/插入、SC 浮层挂载点（帧内 `.live-player-mounter`）。
2. **文档级监听迁移**：帧出现/更换（含帧内导航重载）时，把 `keydown` / `pointerdown` / `fullscreenchange` 与 MutationObserver **显式重挂**到帧文档（MutationObserver 不跨文档继承）；`iframe load` 事件 + 2 秒轮询兜底负责发现变更。
3. **宿主有效性**：`isMounted()` 判定为「已连接 + 归属活动文档一致」，帧换文档后旧宿主立即作废、下一轮自动在帧内重建——**不能用 `isConnected` 单独判定**：旧文档里的元素 `isConnected` 仍为真，会让重建永久卡死。
4. **静音钩子跨 realm（硬约束）**：抽头路径的「可发声判定」要求 MAIN world 静音钩子就绪（见 0011），否则引擎按设计**降级为无增益**。因此 `sniff.js` 加 `all_frames`，在帧的 MAIN world 内安装静音钩子；事件出口从「本窗口」改为显式派发到**顶层窗口**（自定义事件不跨文档，而引擎在顶层监听）。跨源帧派发失败时退回本窗口。
5. SC 显隐沿用「顶层 `document.fullscreenElement` 非空」判定：帧内元素全屏时，顶层 fullscreenElement 即该 iframe 元素，语义天然成立。

**理由与取舍**:
- 备选是「iframe 内独立播放器实例」（帧内代码零改动、更同构），但需要设计双实例职责与消息归属（popup 应答、SC 归属、记忆键一致性）。选择**单实例跨文档**方案：状态、popup、SC 取数链路全部保持原状，改动集中在「查询域」与「监听域」两处抽象。
- 代价：跨文档注入/观察依赖同源前提（已实测同源且跨文档 MutationObserver 可用）；帧内换房重载需重挂钩（load 事件 + 轮询兜底）。
- 记忆键保持顶层地址栏房间号（如 `room:88888`），不随帧内 `blanc/{真实号}` 漂移（见 content.js domSniff 注释）。

**后果**:
- 异形房恢复全功能：按钮（随帧内控制栏 hover 显隐）、增益、快捷键、SC 浮层；跨源帧不可访问时静默退回顶层，行为与修复前一致。
- 普通直播间路径不受影响：无嵌入帧时 `actDoc()` 即顶层文档。
