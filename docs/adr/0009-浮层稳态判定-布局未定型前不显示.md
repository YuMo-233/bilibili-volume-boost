# 浮层稳态判定：布局未定型前不显示

页面加载、懒加载（图片/播放器撑开布局）、换一换等场景下，B 站布局会反复变化。插件浮层挂在 body 上的自有图层、按**文档坐标**定位，若把"当下"测得的坐标立刻画出来，用户看到的便是浮层跟到错误位置、滚动时"跟着跑一段"，随后又突然回正。

## Status

accepted

## 决策要点

- **几何签名 + 静止时长**：每次重定位得到几何签名 `left,top,w,h`；签名连续 `DL_SETTLE_MS`（300ms）未再变化才判定为"稳定"。稳定前给 slot 加 `.bv-unsettled`（`visibility: hidden`），不显示。与 docs/adr/0006 的「控件就绪判定」同一思路，判据从"锚点位置连续两次一致"换成"几何签名静止一段时间"。
- **不依赖外部触发**：未稳定时自行安排一次 `setTimeout` 复核（`_scheduleSettle`），复核后仍变化则继续排下一次；定型即显形，不必等下一次 2 秒轮询或布局事件。
- **稳定后不再抖动**：文档坐标与滚动量无关（换算时被抵消），正常滚动时几何签名不变 → 不会反复隐藏/显形；滚动跟随交给合成器，无逐帧 JS 参与，因此不滞后。
- **只在几何变化时隐藏**：几何不变时保持显示，故"已反馈态"浮层、已显形的 ⋮ 与当前视频开关在正常浏览中不会闪。
- **作用对象**：两个 UI 类共用同一闸门 —— `DislikeCardUI`（推荐卡 ⋮ 与已反馈态浮层）与 `VideoDislikeToggle`（点赞/投币之间的开关）。
- **为什么不在滚动时"重算修正"**：重算并不改变文档坐标（滚动量在换算中抵消），却会把"布局刚变"的中间态画出来，正是本 ADR 要消除的现象。

## Considered Options

- **改成 fixed 定位 + 每帧更新**：需要逐帧 JS 跟随滚动，必然落后合成器 1~2 帧，观感是"黏着但不跟手"；相对 body 图层 + 文档坐标是倒退，否决。
- **等 `document.readyState === 'complete'` 再显示**：视频页图片多且懒加载，complete 时机晚又不稳定，且无法覆盖后续懒加载造成的位移，否决。
- **给元素加过渡动画"抹平"跳变**：位置本身是错的，动画只是把错误拖长；且原生这些元素没有过渡，观感不符，否决。

## Consequences

- 用户看到的是浮层"一次性出现在正确位置"，而不是"错位 → 回正"。
- 布局变化期间浮层会短暂隐藏（约 300ms）后重新显形，这是有意的取舍：隐藏优于错位。
- `DL_SETTLE_MS` 与 adr/0006 的 `SETTLE_MS` 同为 300ms，两处判定节奏一致。
- 若某宿主元素持续动画（几何永不稳定），浮层会一直不显示；当前注入点（操作栏、推荐卡）均为静态布局，不受影响。
