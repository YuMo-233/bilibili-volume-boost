# 0011-抽头失效即整页无声：以「可发声判定」约束静音原元素

**状态**: accepted

**症状**: 进入视频页后**完全没声音**，且不会自愈。此前一次「整页无声」修复（提交 3255a7f，修正钩子初始意图竞态）之后仍复现。

**根因**: captureStream 抽头是静音原元素后的**唯一声源**（见 0010）。原实现**无条件信任抽头**：
- 只要 `ctx.state === 'running'` 就静音原元素，并不校验抽头是否**确有声**；
- 抽头音轨在**媒体源变化**时会 ends（换源 / 换集 / 切清晰度；B 站点播走 MSE，尤易触发），而 `bindVideo` 见到同一元素且 `engaged` 即跳过重挂，抽头死了也不会重抽；
- 一旦抽头失效：原元素被静音 + 本图无输入 = 整页无声，且无任何兜底。

**取证（真实页面实测）**:
- 正常播放时：元素真实 `muted=true`、MAIN world 钩子意图 `false`（意图正确）、抽头音轨 `live / 未 muted` —— 机制本身能出声，说明问题出在抽头失效后的链路而非意图镜像。
- 以「把元素真实 muted 置 false 并触发 volumechange」探测：引擎随即又把真实 muted 压回 true，证明 `ctx.state === 'running'` 且本图确实在接管 —— 即**静音原元素完全押注在抽头这一路**。
- 代码普查：全仓无任何对抽头音轨 `ended / mute`、元素 `emptied / loadstart` 的处理，也无重抽逻辑。

**决策**: 引入**抽头可发声判定**与**抽头自愈**（见 CONTEXT.md「抽头可发声判定 / 重抽」）：
1. **可发声判定**：仅当「上下文 running **且** MAIN world 静音钩子已就绪 `hookReady` **且** 抽头确有声 `tapLive`」时，才静音原元素并放行本图增益；否则原元素保持原生发声、本图增益归零 —— 降级为「只有原生声音、无增益」，**绝不无声**。
2. **抽头自愈**：监听抽头音轨 `mute / unmute / ended` 与元素 `emptied`，失效即**就地重抽**（复用原增益链），取不到则退避重试并立即恢复原生发声。
3. **周期兜底**（1.5s）：抽头 `ended` 则重抽；同时把元素真实静音纠偏到期望值（防被绕过钩子改写）。

**后果与代价**:
- 兜底窗口（钩子未就绪 / 抽头失效 / 上下文未起）内没有增益，只有原生音量 —— 以「绝不无声」换「偶发无增益」。
- `_emitTap === false` 时本图必须静音，否则与原生声音叠加成双份；重抽逻辑带来少量复杂度。

**被否决的备选**:
- **只在抽头 `ended` 时重抽、不设可发声判定**：仍会在「抽头存在但无声」时静音原元素，不满足「绝不无声」。
- **回退 createMediaElementSource 直连**：重新引入换集卡死，见 0010。
