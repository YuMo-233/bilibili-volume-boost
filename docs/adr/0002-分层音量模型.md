# 0002-分层音量模型

**状态**: accepted

**决策**: 原生音量（0–100%）与增益（100%–500%）分层独立。插件完全不修改 B 站原生音量控制，只增加一条独立的增益轨道，最终响度 = 原生音量 × 增益。

**理由**: 被否决的统一音量线方案（插件接管 0–上限% 总音量并联动原生滑块）实现复杂且与原生拖动行为冲突。分层模型让插件对 B 站原生代码零侵入，冲突面最小，最能兑现"融入原生体验"的定位。代价是用户要同时理解两个音量概念，由悬浮滑块与 toast 提示缓解。

**修订（见 0010）**: 改用 captureStream 抽头后，抽头信号**不受元素 `volume`/`muted` 影响**，原生音量层不再自动生效。故本引擎被动接管这层语义：静音原元素避免双份声音，并由 MAIN world 钩子（sniff.js）覆写 `muted` 记录 B 站意图、读 `volume` + 监听 `volumechange`，把 `(意图静音 ? 0 : 原生音量)` 乘进增益。**"不修改 B 站原生音量控制"的对外承诺不变**——插件只**读取** `video.volume` 用于镜像，从不写它，`volume` 仍由 B 站滑块全权掌管；最终响度仍是「原生音量 × 增益」。
