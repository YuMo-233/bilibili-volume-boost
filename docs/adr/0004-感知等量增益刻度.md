# 0004-感知等量增益刻度（Loudness）

**状态**: accepted

**决策**: 增益显示值从"幅值百分比"（100%–500% 线性）改为**感知响度百分比**（50%–500%），遵循 Stevens 幂律（主观响度 ∝ 幅值^0.6）。内部幅值倍率与感知值换算：幅值 g = (L/100)^(5/3)，L = 100·g^0.6。两端由换算自然得出：下限感知 50% = 0.315x（**-10dB**，用于压低过响素材），上限感知 500% = 14.62x（**+23.3dB**）。

**理由**: 用户实测发现线性幅值刻度下"越往上感受越不明显"——100%→200% 只是 +6dB、主观仅 ×1.52，而系统音量滑块（对数映射）50%→100% 约有 ×2.3 的主观提升，造成体感错位。改为感知等量刻度后，拖动/快捷键/刻度每档的听感变化均匀，对齐 Windows 等系统音量滑块的体验。

**300% 是常规/极限分界，不是"无损边界"**: 早期版本曾以"感知 300% = 6.24x（+16dB）仍在无损区间"作为上限论证，该论证已被推翻——**是否产生可听失真取决于素材本身，与档位无关**。实测一条"整体均匀偏小"的稿件（BV12ph76uECQ，对 `__playinfo__` 的 DASH 音频流离线测量）：峰值仅 -9.2 ~ -14 dBFS，主体中位数 **-31.9 dBFS**（p25 -38.4 / p75 -28.5 / p90 -27.2 / p98 -22.5），近静音窗占比 0%。这类素材在 300% 下主体仍只有约 -15.9 dBFS，体感依旧偏小，因此把静态上限抬到 500%（主体约 -8.6 dBFS）；再往上（如 700% → -3.4 dBFS）会全程持续触发限幅，无意义。故 500% 定为上限。

**上限由压缩限幅兜底，并以读数代替承诺**: 管线固定为 `Gain → DynamicsCompressor(-1dB / 20:1 / attack 1ms / release 250ms) → destination`，不做任何"档位承诺无损"的表述。真实是否被压、压了多少，直接读 `DynamicsCompressorNode.reduction`（`AudioEngine.getReduction()`，单位 dB），在面板上以「限幅-NDB」显示（峰值保持 1s）。300% 以上属极限区，UI 用琥珀色区分，提示"此处可能已在限幅"而非"此处仍无失真"。被否决方案：移除压缩保护换取极限数字响度（必然削波爆音）。

**后果**:
- 区间 50–500 全整数，刻度取 50/100/150/200/250/300/400/500 八档，等感知等距；300 以上为极限区（刻度常亮琥珀、填充/滑块/数值变琥珀）。
- 快捷键 `Alt+↑/↓` 每档 ±10 感知值（等感知微调），滚轮 ±5；刻度点击直达八档之一。
- `Alt+0~9` 为等感知十档锚点：`Alt+0`→50%、`Alt+1`→100%，其后每档 +50%，`Alt+9`→500%（见 `content/content.js` 的 `digitBoost`）。
- 历史记忆 v1（幅值百分比）在读取时按幂律自动迁移为感知刻度（v2，钳到当时的 263 上限），用户无感。
