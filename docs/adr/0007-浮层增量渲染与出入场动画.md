# 0007-浮层增量渲染与出入场动画

**状态**: accepted

**决策**: 醒目留言浮层改为**增量渲染**（按 `id` 复用卡片节点），进度条改由 `requestAnimationFrame` **逐帧插值**，出入场动画通过「卡片淡入/淡出 + 承载层高度折叠」实现。

**要解决的问题**: 进度条此前每秒跳一格（`_tick` 每秒写一次 `width`），观感生硬；卡片没有出入场动画。

**为什么必须同时改渲染方式**:
原 `render()` 每次调用都 `wrap.textContent = ''` 整表重建。而 `render()` 由取数轮询驱动，每 10 秒调用一次 —— 若只加 CSS 入场动画，**每轮轮询都会让全部卡片重播一次入场动画**，比不加动画更糟。同理，整表重建无法为「离开列表的卡片」播退场动画（节点已被直接抹掉）。因此增量渲染不是附带优化，而是动画成立的前提。

**理由**:
- 增量渲染：只有真正新增的 `id` 创建节点并播入场动画；离开列表的 `id` 先播退场动画再移除；已有卡片原地更新字段（配色/头像/价格/用户名），不重建、不移动。
- DOM 顺序：按列表顺序逐个把卡片插到前一张之后，已有卡片的相对顺序天然保持（列表已按价格降序），**无需移动已有节点**——移动节点会重启其 CSS 动画。
- 进度条插值：`requestAnimationFrame` 逐帧推进，与真实剩余时间严格对应，不产生「每秒一格」的台阶，也不会像 CSS `transition` 那样滞后一个周期。
- **写 `transform: scaleX()` 而不是 `width`**：`width` 是布局属性，每帧触发 layout，且浏览器会把宽度**吸附到整数像素**。SC 悬挂时长普遍很长（实测 1000 元档为 932 秒），320px 的进度条每秒只推进约 0.34px，被吸附后表现为「每 3 秒跳 1 像素」——此时无论采样多密都会顿。`scaleX` 是合成器属性、不做像素吸附，配合 `transform-origin: left` 与 `will-change: transform` 可真正亚像素平滑，且不引发布局与重绘。这一条是「感觉一顿一顿」的真正成因，不是采样频率问题。
- 仅在缩放值（四位小数）真正变化时才写样式，避免无意义的样式失效。
- 高度折叠：出入场时同时把卡片承载层的高度从 0 展开到自然高度（或反向折叠到 0），否则相邻卡片会在入场瞬间整体下移、退场瞬间整体上跳，动画看起来是坏的。
- 过期清扫：挂在 `requestAnimationFrame` 循环里、每秒至多执行一次。悬挂到点的卡片因此能在 1 秒内播退场动画消失，而不必等下一轮 10 秒轮询。

**取舍**:
- 承载层在动画期间需要 `overflow: hidden` 才能裁掉折叠中的内容，这会把卡片的投影一并裁掉。因此 `overflow: hidden` **只在动画期间挂上**（`.bv-anim`），动画结束即摘除，静止时投影完好。
- 卡片间距由承载层的 `padding-bottom` + 容器的 `margin-bottom: -8px` 实现，替代原来的 `gap`：`padding` 在 `box-sizing: border-box` 下会随高度一起折叠，`gap` 不会。代价是视觉位置有 8px 的负边距偏移，可忽略。
- 动画结束用 `setTimeout` 而非 `transitionend`：浮层可能在被隐藏（`display:none`）状态下发生卡片过期，此时过渡不会触发，`transitionend` 永不回调，节点会永久残留。
- 浮层隐藏时暂停 `requestAnimationFrame`，重新显示后按真实剩余时间重新计算进度，不会累积漂移。
