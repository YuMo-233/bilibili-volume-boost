# 0005-全屏醒目留言浮层：自绘复刻 + HTTP 轮询

**状态**: accepted

**决策**: 直播间沉浸全屏下的醒目留言（SC）显示，采用 **HTTP 轮询取数 + Shadow DOM 自绘卡片**，注入点为播放器列内的 `.live-player-mounter`（全屏随行，四角定位、默认右上）。**不搬运** B 站原生 `pay-note` 面板 DOM 节点，**不拦截**页面 WebSocket。

**痛点根因（实测）**: 原生 SC 面板 `#pay-note-panel-vm` / `.pay-note-setting` 位于右侧栏 `.aside-area`（内含 `.chat-overlay-layer`），与播放器列 `.player-ctnr` 是**兄弟节点**；全屏时 B 站给 `<body>` 加 `hide-aside-area`，且沉浸全屏（Fullscreen API）本身只渲染全屏元素子树。实测 `document.querySelector('.player-ctnr').querySelectorAll('[class*=pay-note]').length === 0`——SC 完全不在播放器内，全屏必然看不见。

**原生卡片结构（实测）**:
```
.pay-note-setting > .pay-note-panel > .card-list > .card-wrapper
  └ .card-item-box.child > .card-item
      ├ .totle        ← 背景色块（实测 rgb(229,77,77)）
      ├ .progress     ← 悬挂倒计时进度条
      ├ .face-img     ← 头像
      └ .price > .currency-icon（base64 电池图标） + .price-tag
```
默认**只显示头像 + 价格 + 进度条**，留言内容需点击卡片弹出详情才可见。

**数据源（实测）**:
```
GET https://api.live.bilibili.com/av/v1/SuperChat/getMessageList?room_id={roomid}
```
**无需登录**返回 `code:0`，含当前悬挂中的全部 SC 及其完整字段：`id` / `uid` / `price`（单位：元）/ `message` / `start_time` / `end_time` / `background_color` / `background_price_color` / `background_bottom_color` / `font_color` / `token` / `user_info{ uname, face, guard_level }`。实测 `background_bottom_color: "#E54D4D"` 与页面原生卡片色块 `rgb(229,77,77)` 完全一致。

**理由**:
- **SC 是长悬挂内容**（最短 60 秒、最长 2 小时），10 秒轮询不会漏任何一条，延迟在体感上无影响；这与转瞬即逝的弹幕有本质区别。
- HTTP 端点字段齐备，**自带精确配色**（`background_bottom_color` 等），自绘无需硬编码价格色阶、也无需猜测。
- 原生卡片默认不显示留言，而 SC 的核心价值就是留言内容；且其结构依赖 `pay-note-*` / `card-item-*` class，B 站改版即失效。自绘仅依赖 HTTP 接口字段。
- 多卡叠放、价格排序、上限折叠、手动关闭等交互由插件完全可控。
- 单一路径取代"WS 增量 + HTTP 回填"双路径，取数模块大幅简化，`sniff.js` 无需改动。

**被否决方案**:
- **拦截页面 WebSocket**（原方案）:B 站直播弹幕包用 **brotli** 压缩（protover 3），而浏览器原生 `DecompressionStream` 仅支持 `gzip` / `deflate` / `deflate-raw`，**不含 brotli**。走此路必须额外 bundle brotli 解码器、在 MAIN world 劫持 `WebSocket` 构造器、自行拆二进制包头与分片——为不足 10 秒的延迟优势付出数量级更高的复杂度与失效风险。
- **自建 WebSocket**（protover 2 走原生 deflate）:可规避 brotli，但需自行处理认证包/心跳/重连，且游客连接存在限流风险。
- **搬运原生面板**（实测可行）:移入 `.web-player-inject-wrap` 后稳定渲染，Vue 6 秒内未回收节点、可正常还原。但存在"留言不常显 + class 易变 + 样式需覆写 + 多卡排序不可控"四项代价。
- **DOM 监听原生卡片**:无结构化字段（无 uid / 价格数值 / end_time），且 class 易变。

**已知取舍**:
- 注入点选择播放器列内的 `.live-player-mounter`（与 `<video>`、`.web-player-inject-wrap` 同级），保证沉浸全屏与网页全屏下都在播放器/全屏元素内。
- 卡片视觉为"高保真复刻"而非"字节级一致"：以服务端色值 + 头像 + 用户名 + 价格 + 留言五要素还原；电池图标等 B 站私有资源不自带。
- 轮询存在最多一个轮询间隔的显示延迟；SC 从列表消失（悬挂结束或被删除）即视为移除，与 B 站原生行为一致。

**落地细节（已定）**:
- 数据源：HTTP 轮询 `getMessageList`，间隔 10 秒；以 `id` 为主键做增量合并，接口中消失的 `id` 判为已移除。轮询在仅在直播间页面、且 SC 开关开启时运行。
- 首次轮询即完成"初始回填"：进入页面/开启开关时立刻拉一次，带回当前全部悬挂中的 SC，不存在历史遗漏。
- 显示时机：仅沉浸全屏（网页全屏/普通状态不显示，避免与原生公屏 SC 重复）。
- 生命周期：显示至该条 `end_time`，支持手动关闭；被删除的 SC 因从接口消失而自动移除。
- 叠放：按价格降序纵向排列，最多 3 条，超出折叠为 "+N 条"。
- 过滤：默认全部显示，不设价格阈值。
- 开关：popup 独立开关（与音量总开关分离），默认开启。
- 显示位置：popup 提供左上 / 右上 / 右下 / 左下四角可选，默认右上；仅作用于 SC 浮层，音量滑块仍跟随原生控制栏。
- **房间号必须先换算成真实房间号（实测踩坑）**：URL 首段数字可能是**短号**（`live.bilibili.com/88888` 的 `short_id=88888`，真实 `room_id=3947892`），而直播接口**只认真实房间号**——`getMessageList?room_id=短号` 返回 `code:-1「系统繁忙,请稍后重试」`，导致该房间 SC 永远取不到数据（表现为"SC 不显示"）。故取数前先经 `room/v1/Room/room_init?id={路径号}` 换算出 `room_id`（免登录），按路径号缓存并防换房竞态；换算完成前不启动取数，避免整轮报错。注意房间号相关接口（含 UP 主识别）都应使用真实房间号。
