# 0012-新版直播播放器锚点迁移与就绪信号

**状态**: accepted

**症状（实测，2026-10）**: 直播间的增益按钮位置不再确定：部分直播间 hover 时才勉强落在音量键旁（实为控制栏空壳的布局巧合），部分直播间整段时间 0×0 完全不可见；面板与拖动交互随之不可用。

**根因（真实页面取证）**: B 站直播已全量切换新版播放器（Svelte 构建）：
- 旧锚点 `.web-player-icon-volume` / `.webplayer-volume` / `.web-player-controller-right` 在标准房（6838597）、VTuber 房（21452505）、活动房（88888）实测**全部为 0**；
- 旧槽位 `.web-player-controller-wrap` 仍存在，但退化为**空壳背景层**——`mount()` 成功把宿主塞进去，落点由未定义布局决定（实测同实现在不同房间一显一隐）；
- 控制栏（`.live-web-player-controller` → `.control-area` → `.left-area` / `.right-area`）由 Svelte 在**鼠标悬停时动态挂载、离开后整体卸载**；音量按钮真实类是 `div.volume`（scoped 哈希类不可依赖），`.right-area` 尾部另有官方扩展槽 `.ext-nodes`。

**决策**:
1. 锚点选择器新增 `.control-area .volume`（插入其右侧即「音量键旁」），槽位新增 `.control-area .left-area`；旧选择器**保留为后备**，仅在新版未命中时按序回退（防灰度回滚/房间版本差异）。
2. 按钮**随控制栏 hover 显隐**（与原生控件同生命周期）：控制栏挂载时迁入锚点右侧；宿主**只建一次**，控制栏卸载/重挂时复用重插，保住模板、事件绑定与一次性就绪闩锁。
3. 就绪信号修订（CONTEXT.md「锚点」「控件就绪」同步更新）：不再要求锚点常驻——**控制栏已挂载**即代表可注入；锚点存在时仍做「可见 + 位置连续两次采样一致」判定，5 秒兜底放行保留给锚点缺失的播放器变体。

**理由**:
- 位置必须由锚点决定而非容器布局巧合：新版播放器下把宿主放进空壳的落点是未定义行为（实测同一实现两种结果，见症状）。
- 复用宿主而非每轮重建：重建会重放模板与事件绑定、重置就绪闩锁；hover 频繁时重建还会有可见闪烁。
- 旧选择器保留成本近零：只在单选查询的回退序列里多两条字符串。

**取舍与后果**:
- 控制栏不可见期间没有插件按钮（与原生音量键一致），不作为常驻入口；快捷键与记忆应用不受影响。
- 锚点限定在 `.control-area` 内，避免误伤聊天区等处的其它 `.volume` 元素。
- 首次 hover 后按钮约 300ms 显形（沿用 0006 的两次采样），预览气泡 toast 不受影响。
