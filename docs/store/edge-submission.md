# Microsoft Edge 加载项提交材料

本文件汇总提交到 **Microsoft Edge 加载项**商店所需的全部字段内容，可逐项复制粘贴到 Partner Center。

配套文件（**不纳入仓库**，位于仓库外的 `d:\app\dist\edge-store\`）：

| 文件 | 用途 | 是否必需 |
| --- | --- | --- |
| `bili-volume-boost-1.3.4.zip` | 待上传的扩展包（**当前版本**） | 必需 |
| `store-logo-300.png` | 商店徽标，1:1 | 必需（推荐 300×300，最小 128×128） |
| `screenshot-*.png` | 商店截图 | 可选（640×480 或 1280×800，最多 6~10 张） |

**打包规则**（与已上架版本保持一致）：zip 内**只含运行所需文件**，且**不含顶层目录**——`manifest.json` + `content/*.js` + `popup/*` + `icons/*` + `_locales/*`，共 19 个文件。`docs/`、`README.md`、`LICENSE`、`PRIVACY.md`、`CONTEXT.md`、`scripts/` 一律不进包。

打包**不要手工拖拽压缩**，一条命令即可（版本号自动取自 `manifest.json`，并且会打印 sha256 供核对）：

```bash
python scripts/pack-store.py
# → d:\app\dist\edge-store\bili-volume-boost-<version>.zip
```

## 1. 包与清单校验

### 1.1 商店一览的「显示名称 / 简短说明」

manifest 中这两个字段会**自动填充商店一览，且为只读**，上传前需确认已符合预期。从 `1.3.4` 起它们不再硬编码，而是走 i18n 引用：

| 商店字段 | 来源 | 当前值 |
| --- | --- | --- |
| 显示名称 | manifest `name` = `__MSG_extName__` | `B站音量增强` |
| 简短说明 | manifest `description` = `__MSG_extDesc__` | `为 B 站视频与直播提供 50%-500% 音量增益（按 UP 主记忆，不破坏原生沉浸全屏），直播沉浸全屏时可在画面角落显示醒目留言。非官方第三方扩展，与哔哩哔哩无关联。` |

实际文案在 `_locales/zh_CN/messages.json` 里的 `extName` / `extDesc` 两个键，改文案改那里即可，manifest 不用动。

### 1.2 为什么必须走 i18n（商店一览语言的根因）

**商店一览里显示哪种语言，不是靠 Partner Center 的下拉框选的，而是从扩展包内的 i18n 引用推断出来的。** 微软官方文档（[Publish an extension](https://learn.microsoft.com/en-us/microsoft-edge/extensions/publish/publish-extension)）写明：

> Partner Center uses these message references to identify available languages. If these message references are missing, the language will be skipped.

而「包里有中文却只显示一个语区」的情形，文档归因于一句：

> the manifest file uses hardcoded strings instead of localized message references.

`1.3.3` 及更早的包里 `name`/`description` 是硬编码中文字符串、又没有 `default_locale`，所以 Partner Center 认不出任何语区，只能回退标成一个语言项——就是我们看到的「英语(美国)」。**这是包的问题，在页面上怎么点都改不掉。**

要让商店一览出现「中文（简体）」，包里必须同时具备三件事（`1.3.4` 起已全部满足）：

1. manifest 的 `name` / `description` 用 i18n 占位符（`__MSG_extName__` / `__MSG_extDesc__`），不用硬编码字符串；
2. manifest 声明 `"default_locale": "zh_CN"`；
3. 存在 `_locales/zh_CN/messages.json`，且结构正确、包含占位符引用的键。

> 页面上那个「添加语言」下拉框只能**追加**语言项，不能修正已有语言项的语区标签；语言的**识别**始终由包决定。因此改语言 = 改包 + 重新上传，没有纯 UI 的捷径。

## 4. 步骤 6：隐私（Privacy）

### 4.1 单一用途说明

```
本扩展为哔哩哔哩（bilibili）网站的视频页与直播页提供两项增强：一是音量增益，让用户可以把播放音量提升到网站原生上限（100%）之上，并按 UP 主分别记忆；二是在直播沉浸全屏时，把当前直播间悬挂中的醒目留言（Super Chat）显示在播放器画面角落，因为沉浸全屏下网站原生的留言侧栏不可见。
```

### 4.2 权限理由（逐个权限）

**`storage`**

```
用于在本地保存用户的音量增益设置：插件总开关，以及按 UP 主分别记录的音量增益值（视频页按 UP 主 mid、直播页按主播 uid 分桶），以便用户再次观看同一 UP 主的视频或直播时自动套用上次的增益。另保存醒目留言浮层的开关与显示位置。全部数据仅存于用户本地浏览器的 chrome.storage.local，不上传、不共享，用户可在扩展面板中一键清空。
```

**`activeTab`**

```
用于扩展的 popup 面板在用户点击扩展图标时读取当前标签页的地址，以判断当前是哔哩哔哩视频页还是直播页，从而只显示该页面对应的设置项（直播页显示醒目留言浮层的开关与显示位置，视频页显示「不感兴趣」相关设置），并显示识别到的主播与当前增益值。扩展不读取页面正文内容，不使用该权限做任何其他用途。
```

**`https://api.live.bilibili.com/*`**

```
直播页需要读取哔哩哔哩官方的醒目留言列表接口（GET /av/v1/SuperChat/getMessageList?room_id=<直播间号>），以获取当前直播间正处于悬挂展示中的醒目留言内容，进而显示在沉浸全屏下的播放器角落。该请求由用户当前打开的哔哩哔哩直播间页面发出，每隔 10 秒一次，只读取该直播间公开可见的留言内容；扩展不向该接口发送任何用户数据，不收集、不存储接口返回内容以外的信息，也不与任何其他服务器通信。该权限是本扩展除本地存储外唯一的网络访问。
```

### 5.1 详细说明

```
【它解决什么问题】

哔哩哔哩的音量滑块最高只有 100%。当源视频或直播本身录制音量偏小、设备音量已开满时，你就没有别的办法了。本扩展在网站原生音量之上叠加一条独立的「增益」轨道，把可调范围扩展到最高 500%（约 14.62 倍幅值、+23.3dB），并且按 UP 主分别记忆——下次进同一个主播的页面会自动套用你上次设定的增益。

另一件事：在直播间进入沉浸全屏后，网站右侧的醒目留言（Super Chat）侧栏会被隐藏，此时你看不到任何留言。本扩展会在全屏画面的角落把当前悬挂中的醒目留言显示出来，包含头像、用户名、金额和留言正文。

【音量增益】

· 范围 50%–500%，默认 100%（不改动时与你原本听到的完全一致）
· 采用感知等量刻度：滑块每一档的听感变化都相同，越往上不会觉得「越调越不明显」
· 分层设计，不修改网站原生音量滑块，最终响度 = 原生音量 × 增益
· 内置压缩限幅，极限增益下也不会出现削波爆音
· 按 UP 主记忆：视频页与直播页分别记录，各自独立
· 滑块就在原生音量按钮旁边，鼠标悬停展开，支持拖动与滚轮微调

【直播全屏醒目留言】

· 仅在「沉浸全屏」下显示，避免与页面原有的留言栏重复
· 可设置显示在画面四角之一（默认右上）
· 卡片配色取自留言数据本身，与网站原生配色一致
· 同时悬挂多条时按金额从高到低排列，最多显示 3 条，更多则折叠为「+N 条」；其中一条悬挂结束时，折叠中的留言会**立即**补位并刷新计数，无需等待或刷新页面
· 可逐条手动关闭

【快捷键】

· Alt + ↑ / ↓ —— 增益 ±10%
· Alt + 0–9 —— 快速定档
· Alt + M —— 静音切换
· 光标位于输入框内时快捷键自动放行，不会影响你打字

【隐私】

不收集、不上传任何个人信息，无统计、无广告、无远程代码。所有设置只保存在你自己的浏览器本地，卸载即清除。

【说明】

本扩展为第三方个人开源项目，与哔哩哔哩官方无任何关联。源码与反馈：https://github.com/YuMo-233/bilibili-volume-boost
```
