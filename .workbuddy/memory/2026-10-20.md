## 接入 Edge 发布 API（替代手动上传）

- 上面那条「只能人工」只在**浏览器自动化**层成立。改用官方 **发布 API** 后上传与提交审核都能脚本化：`scripts/publish-edge.py`（status / init / upload / publish / watch）。网关 `https://api.addons.microsoftedge.microsoft.com`，v1.1 认证头 `Authorization: ApiKey <key>` + `X-ClientID`。
- **元数据无法过 API**：官方明确没有更新产品信息的端点，名称/简介/详细说明/截图/搜索词只能进 Partner Center。
- 接口：`POST /v1/products/{pid}/submissions/draft/package`（body 为 zip 原始字节，`Content-Type: application/zip`）→ 202 + Location 里的 operationId → `GET .../draft/package/operations/{opId}` 轮询；`POST /v1/products/{pid}/submissions`（body `{"notes": "..."}`）→ `GET .../submissions/operations/{opId}`。productId = `8d677011-d896-47eb-90a9-34b058d00fed`。
- **踩坑一（最坑）**：密钥有效期只有 **72 天**（本例 10/20 建、12/31 到期），不能续期不能延长；**重建凭据会同时换掉 Client ID**。只更新 key 不更新 Client ID 会得到 `403 Client ID is Invalid`——看着完全不像过期。本次就撞上了：22:34 截图那对凭据在 22:35 被重建，旧对即时作废。
- **踩坑二**：上传返回 202 只代表收到，校验失败时 **HTTP 仍 200**，原因在轮询返回的 JSON 里。必须轮询，否则会误报成功。
- **踩坑三**：包内不允许有压缩文件（校验器读魔数），Edge 独有；本项目只打 JS/PNG/JSON，不受影响。
- 诊断技巧：403 时打印响应头 `reason` 才能看到真正的 `Client ID is Invalid`，只看状态码会误判成"密钥未生效"。
- 凭据存放：`d:\app\dist\edge-store\credentials.json`（仓库外）；`.gitignore` 加了 `credentials.json`、`credentials*.json`、`*.key`、`*.pem`、`.env*` 防御规则。脚本输出只给掩码。`init --from-clipboard` 从剪贴板取密钥，避免明文进对话或 shell 历史。
- 文档：`docs/store/publish-api.md`（能力边界、排错表、分工）；`edge-submission.md` 里「上传必须人工」的旧结论已更正。
