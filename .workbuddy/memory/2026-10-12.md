# 2026-10-12

## 修复：SPA 导航后 UP 主不更新，旧增益套用到下一个视频（v1.3.1）

**根因（三处叠加）**
1. 全仓没有任何 URL 变化监听；B 站视频页之间是同文档导航，content script 不重新注入。
2. `sniff.js` 只在加载期轮询 `[500,1500,3000,6000]`ms 就永久停手，导航后不再重读 `__INITIAL_STATE__`。
3. `domSniff()` 的短路闸门 `hasUpEvent[type] && current.mid` 置真后永不重置 → DOM 兜底永久失效。
   → `current.mid` 停在旧 UP 主 → `setCurrent` 的 changed 判定不成立 → 不重新应用记忆 → 引擎单例上的旧增益留存。
4. 附带缺陷：`applyMemoryGain()` 在 `memo == null` 时什么都不做，"新 UP 主没记忆"同样残留旧增益。

**改动**
- `content/sniff.js`：拆出 `probe()`（只读不派发）；顶层窗口包装 `history.pushState/replaceState` + 监听 `popstate/hashchange`；导航时派发 `bv_boost_nav`，随后 `readUntilFresh()` 读到 UP 主变化为止再派发 `bv_boost_up`（间隔 250ms / 放宽期 1200ms / 兜底至 8000ms）。嵌入帧不挂钩（`window.top === window` 判定）。
- `content/content.js`：新增 `pageIdentity()`（视频页取 bvid，`/list/` 的 bvid 在 query；直播页取路径首段数字）、`resetIdentification()`、`armNavFallback()`（2.5s 未识别出则回默认 100%）、`reinstate()`（七步链路的唯一入口，引擎不 teardown）；`applyMemoryGain` 改为 `setBoost(memo != null ? memo : 100)`；`init` 先挂监听再读存储，2s tick 改为 `onNavigation() + reinstate()`。
- `manifest.json` 版本 1.3.0 → 1.3.1。
- 文档：CONTEXT.md 新增「页面生命周期」小节（SPA 导航 / 页面身份 / 重识别）；新增 `docs/adr/0015-SPA-导航-页面身份与重识别.md`。

**验证**：临时 stub 测试（`%TEMP%/bv-nav-smoke/`，未入仓）——sniff 导航时序 4 场景全 PASS；pageIdentity 13 条真实 URL 形态全 PASS。

**项目约定**：仓库无测试基础设施；验证靠浏览器自动化 + `bv_boost_debug` 调试钩子（dump 到 `<html data-bv-dbg>`，已加入 `identity` 字段）。
